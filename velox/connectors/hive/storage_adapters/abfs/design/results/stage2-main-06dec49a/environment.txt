Sanitizer prerequisites
- Clang 20 and compiler-rt were extracted into a user-owned WSL toolchain.
  No system package was installed and no privileged command was used.
- Both sanitizer trees use the pinned bundled Folly source. Mixing
  sanitizer-enabled Folly headers with the prebuilt system libfolly aborts in
  the fiber stack-switch protocol and is not valid sanitizer evidence.
- The ASAN tree compiles all bundled Folly and ABFS objects with
  -fsanitize=address. Folly's generated library sanitizer marker is set to 1
  in that build tree so its sanitizer fiber-switch wrappers dispatch to the
  linked compiler-rt hooks. Repository source is not patched for this marker.
- TSAN commands run through setarch x86_64 -R. Without process-local ASLR
  disablement, even an empty GCC or Clang TSAN program can fail before main
  with an unexpected-memory-mapping error under this WSL kernel.

Security and privacy

- No public DNS, Azure endpoint, account identifier, credential, SAS value,
  authorization header, username, hostname, or private absolute path is
  retained in repository evidence.
